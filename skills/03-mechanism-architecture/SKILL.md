# 机制驱动的表示与架构

## 适用情形与输入

用于明确研究问题后设计模型或审核方法。输入为目标能力、初步机制、部署信息、可用数据和资源。机制仍不清楚时，先做能定位信息、容量或协议瓶颈的小型诊断。

## 1. 定义信息与表示

列出输入实体、语义或物理变量、局部与全局关系、时序、模态、对称性和可变规模。确定哪些量必须显式保留，哪些可以压缩，哪些需要历史，以及最终怎样读出任务结果。

显式变量便于施加结构、监督和外部查询；潜在状态适合压缩余下信息。两者按任务组合。评价压缩时同时看所需预测能力与存储成本，避免把当前重建好等同于未来信息充分。

## 2. 画依赖图并寻找复用

标明每个输出必需依赖哪些输入，查询之间是否需要交互。多个独立查询共享上下文时，可先完成一次上下文编码，再用轻量读出；查询相互作用是任务的一部分时，为其设计交互。

区分观察上下文的范围与实际输出作用范围。某个局部输出可以读取更大范围上下文，但是否有效需要实证。编码器的连接方式由信息依赖决定，不由输出恰好能写成矩阵或图决定。

## 3. 选择能够表达机制的最小充分结构

先建立有效的简单主干，再为每个必要改变记录四项：读取什么、新增什么能力、代价是什么、什么实验能区分该设计与简单替代。

MLP 可作为局部函数基线，卷积适合规则共享计算，集合聚合处理可变数量输入，图消息传递表达局部关系，注意力提供内容相关选择，循环或状态空间模块承担持续状态更新。它们是候选工具，不是固定的优劣顺序。

缩放深度或宽度可以是核心研究选择。用固定数据或经验、合理调参和多个预算区分容量、优化及数据变化，确认增大规模对应真实瓶颈。

## 4. 闭合完整计算链

写出输入→编码→状态→交互／更新→读出→实际损失。标出张量形状、参数共享、归一化轴、掩码、邻域、初始化、随机性和训练／推理差异。循环状态须说明参考答案离开后如何自主更新。

学习权重时区分内部特征注意力与实际物理或概率权重。使用约束投影、局部求解或归一化分母时，明确它们是否参与反向传播、何时可解，以及异常构型如何处理。

## 5. 数学、实现与成本检查

检查量纲、输入极限、退化样本、排列和坐标变化。需要声明守恒或等变时给出适用条件，并区分硬结构、损失促进与经验观察。小规模人工例子用于核对代数、输出与梯度，记录真正执行的检查。

按实际张量估算内存，尤其是高维边状态和注意力矩阵；按流水线计算建图、索引、编码、求解与读出。检查稀疏声明是否由稀疏实现兑现，以及跨查询复用的开销是否可摊销。

## 6. 裁决架构的贡献

按主张选择同数据同目标的简单结构、同结构不同目标、同状态预算的固定表示、同总预算的深宽对照，以及临时提供精确信息的参考模块。加入状态交换、输入替换或依赖关系干预，避免只通过删除模块解释机制。

输出完整计算说明和设计表：模块｜假设｜输入输出｜代价｜简单替代｜区分实验。验收要求每项关键结构有明确作用、至少一种可检验差异及端到端可实现接口。收益来自数据或目标时，相应调整贡献归属。
