# 问题发现与可检验假设

## 适用情形与输入

用于选题、解释失败、判断创新性或重新定位瓶颈。输入为使用目标、已有方法与结果、可见信息、预算和文献线索。先明确能力需求，再决定采用哪种网络或学习范式。

## 1. 定义有意义的缺口

从真实使用与评测的差异、相似输入的不同未来、稳定重复的异常、表示遗漏、训练目标偏差或高成本环节寻找候选。

为每个候选写清使用者、输入、输出、现有能力、尚缺能力和解决后的价值。检查指标是否能区分目标能力；必要时先改测量协议。保留少量候选进行低成本探索，在大规模训练前收敛到一项主要判断。

## 2. 建立竞争解释

对观察提出少量能够区分的原因，例如信息不足、表示不合适、容量不足、优化问题、数据覆盖、部署协议和测量失真。对每个原因写出可观察预测，而不是仅列标签。

新能力尚无失败事实时，先检验关键可行性假设，例如输入是否足以识别目标、评价是否能量化新增能力。已有结果、推导和猜测分别标注。

## 3. 选择最有信息价值的诊断

按可能改变决策的程度安排下一步：

- 信息：保持所有实际可见输入一致，改变隐藏因素；或让一个参考模型临时获得缺失信息，估计其价值。
- 数据与容量：固定网络改训练覆盖；固定经验或数据改网络规模；分别控制优化与调参预算。
- 协议：保持信息总量不变，改变呈现顺序、反馈时机或自回归方式。
- 机制：保持某些统计量，改变被解释变量；在更简单系统中检查现象是否仍存在。
- 效率：提供理想或高成本子模块，检查即使子模块很好，完整任务是否还有收益空间。

按当前主张选择必要诊断，避免为每个项目执行全部清单。预先记录预测、样本与预算、测量灵敏度及结果对应的决策。

## 4. 从诊断选择设计对象

如果缺口来自测量，改评价；来自不可辨认的信息，改输入、状态或目标；来自表示依赖，改编码与连接；来自经验分布，改采样和训练；来自真实计算，改复用与调度。

这个映射是起点，允许多种解释共存。简化系统产生现象可证明一种解释足够，但不能自动说明它主导真实任务；一次反例可以排除过强命题，仍需检查剩余解释。

## 5. 确定研究边界与下一决策

给最小诊断设预算和停止点。没有明显信号时先检查误差尺度、统计能力和实现。便宜方法已经充分解决问题时，将贡献定位到有效发现或转向尚有价值的边界；机制成立但方法无效时，保留问题并重设设计。

输出问题卡：对象与价值、任务输入输出、部署信息、证据状态、竞争假设、区分实验、最近邻差异和下一步。可使用[问题模板](../../templates/problem_card.md)。

通过条件是问题有明确价值、至少一种可行诊断、剩余差异值得检验；无需在探索开始前证明最终方法必然成功。
